Architecture · sysbench-cpp 1.0

sysbench-cpp

A C++26 port of sysbench built around four invariants: one memory reservation, one scheduler that owns every wait, one io_uring ring per socket, and an explicit Result<T, E> at every fallible boundary. The original Lua benchmark API runs unchanged on top.

C++26 · coroutines · io_uring · Lua 5.4 · NUMA-aware · Linux 5.19+

01 · Shape of the process

Few OS threads, many benchmark tasks.

--threads sets benchmark tasks (coroutines), not OS threads. --workers sets runtime worker threads, capped at 64. When tasks outnumber workers, a task simply yields every 128 events so the others run.

The main thread loads the bootstrap Lua state, collects custom options and prints reports from a reserved CPU on its home NUMA node. Worker threads are assigned round-robin across online nodes, pinned to a node-local CPU mask, and given a node-bound heap.

  • Runtime owns every thread it creates: workers, one reaper per socket, and test fixtures.
  • No work stealing. Lua states, connections, arenas and registered buffers are thread-affine.
  • Node-local by construction: heaps, control blocks, buffers and coroutine frames are mbind-bound before first touch.

02 · Memory

One mapping. Everything else is a carve.

The root mmap is the only OS allocation the project makes. A per-worker HeapArena handles long-lived, arbitrary-order allocation; a task-owned BumpArena handles event-lifetime results. Each event opens a ScopedAllocator, and its destructor rewinds the bump arena in O(1).

Coroutine frames come from per-node 1 MiB slabs with per-thread size-class caches. Frame memory is recycled, never returned to the OS. Lua states, MySQL packets, result sets and STL containers all allocate through the same hierarchy.

  • RootArena: 4 GiB default, MAP_NORESERVE; optional up-front population.
  • HeapArena: boundary tags, coalescing, 40 size bins; one per worker.
  • BumpArena: 256 KiB event scope; deallocation is a no-op.
  • Result lifetime: valid until the next event begins — exactly what OLTP scripts assume.
  • No application-level new or malloc in the project.

03 · Scheduling

The Runtime decides every wait.

Task<T> promises are lazy and are started only by the Runtime. Awaited children start with symmetric transfer, so a nested MySQL call does not pay a scheduler turn per level; the final awaiter transfers to its continuation directly.

Completions arrive on a lock-free intrusive injection stack. A worker drains it before touching its ready list. Workers spin briefly only when the runtime is undersubscribed; otherwise they park so the CPU can run another task, even one whose I/O is on a different socket.

  • No work stealing: continuations stay on the owning worker.
  • Lost-wakeup safe: the injection push and the parked flag are seq_cst, closing the store-buffer interleaving.
  • Worker-local timers for sleeps and rate pacing; no global timing wheel.
  • Deferred destruction keeps an awaited child's frame alive until the resume unwinds.

04 · Transport

Submit on the worker, reap on a reaper.

Each socket owns one io_uring. The owning worker is the sole SQ submitter; it drains a 512-entry lock-free request ring in batches and calls non-blocking io_uring_submit. It never waits for a completion.

A Runtime-owned, node-pinned reaper thread waits on the ring's CQ eventfd and a shutdown eventfd. It posts suspended coroutines back through the worker's injection stack. Reads and writes use READ_FIXED/WRITE_FIXED over the socket's registered buffers; connect and accept are native ring operations.

  • No IORING_SETUP_COOP_TASKRUN: it would defer notification to the submitter's kernel entries and stall the eventfd.
  • No mutex, rwlock or condition variable guards the ring.
  • No allocation per operation: IoCompletion lives in the awaiting coroutine frame.
  • Fast teardown: the shutdown eventfd releases the reaper immediately (~0.1 ms, not a 100 ms timeout).

05 · Protocols and Lua

A neutral interface, one wire implementation, the original script API.

Benchmarks see db::Connection, db::PreparedStatement and db::Driver, never MySQL details. Every fallible call returns Result<T, db::Error>; errors are values, handled explicitly at the call site.

Below that, PacketChannel owns framing, packet sequencing, registered-buffer leases and optional TLS via OpenSSL memory BIOs. The MySQL codec is pure and can be tested without sockets. Lua keeps the original API because each query yields the Lua coroutine while C++ awaits the ring.

  • MySQL only in this build, but the registry is open: a new driver needs no Lua or scheduling changes.
  • Text + binary: COM_QUERY, prepared statements, multi-result draining, chunked bulk inserts.
  • Auth: mysql_native_password and caching_sha2_password fast/full RSA.
  • TLS: off / preferred / required, optional CA, hostname check and client certificate.
  • One boot state for options and report hooks; one Lua state per benchmark task on its worker.

The Lua bridge in five moves

  • con:query() calls a C function that records the pending operation.
  • The C function calls lua_yield, suspending the Lua coroutine.
  • The C++ task driving thread_run performs the query with co_await.
  • The result handle is pushed onto the suspended Lua stack.
  • lua_resume returns it as an ordinary value; pcall and the script see nothing unusual.

06 · Statistics and locality

Counters that never share a cache line.

Every hot counter is a ShardedCounter: one cache-line-aligned atomic per shard, indexed by worker or benchmark thread ID, updated with relaxed ordering. Threads write only their own line, so a counter update cannot bounce the line between cores.

Reports aggregate shards without stopping workers. The event limit is checked in batches of up to 64 events per thread, so a multi-threaded --events stop point can overshoot by at most batch × threads; single-threaded limits are exact.

  • ThreadStats is alignas(64): latency histogram and all per-thread counters share no line.
  • Owner-local min/max fast paths avoid compare-exchange loops on every event.
  • Per-socket ring counters are naturally sharded by the connection.
  • Aggregation only at report time, never in the event loop.
